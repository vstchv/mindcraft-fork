# This fork: local voice and gameplay additions

> **Fork-specific documentation.** This section describes the additions in this repository. The original Mindcraft README starts below the divider.

## What we added

- **Local spoken replies:** Kokoro text-to-speech runs on the CPU and plays Andy's replies through your desktop speakers. Speech is split into short phrases, and stale queued replies are discarded when a new reply arrives.
- **Push-to-talk:** a local browser microphone panel transcribes English speech with Whisper and sends it to Andy. Hold **F8** on Windows or use the panel's push-to-talk button.
- **Local configuration:** `.env` holds your LM Studio endpoint and Minecraft player name; `.env.example` contains shareable placeholders. Local `.env` files and downloaded model caches are ignored by Git.
- **Fishing:** the `!fish()` command looks for nearby exposed water, checks for a clear casting direction away from players, casts once, waits up to 45 seconds for a bite, and checks inventory before reporting a catch.
- **Conversation and action changes:** Andy's profile emphasizes the latest player request, avoids continuing old goals, and reports unconfirmed or failed actions. Fishing rods are blocked from generic `!useOn` use to avoid hooking players.

## Set up this fork

1. Use **Node.js 22 LTS** for this fork; automatic `.env` loading uses Node's built-in `loadEnvFile`. Install **FFmpeg**, with both `ffmpeg` (microphone audio conversion) and `ffplay` (speech playback) available on your `PATH`.
2. Run `npm install` from the repository folder.
3. Copy `.env.example` to `.env` and edit the local values:

   ```dotenv
   LM_STUDIO_URL=http://localhost:1234/v1
   MINECRAFT_PLAYER=YourMinecraftName
   ```

   Set `LM_STUDIO_URL` to your LM Studio server's OpenAI-compatible endpoint, including `/v1`. Use your exact in-game name for `MINECRAFT_PLAYER`. Keep personal values in `.env`.
4. Start the LM Studio server and load the chat and embedding models named in `andy.json`. The included profile uses `qwen/qwen3.5-9b` and `text-embedding-nomic-embed-text-v1.5`; adjust these names to match your installed models. Both use `LM_STUDIO_URL` unless an explicit profile URL is supplied. This local setup needs no paid API key.
5. Start Minecraft Java Edition, open your world to LAN, and match `host`, `port`, and `auth` in `settings.js` to your server. The included configuration uses localhost port `55916` with offline authentication.
6. Start Andy:

   ```sh
   npm start
   ```

## Talk to Andy

Spoken replies are enabled by `speak: true` in `settings.js`. Select a Kokoro voice through `speak_model` in `andy.json`, for example `kokoro/kokoro-82m/am_fenrir`. Audio plays on the machine running Mindcraft. The first use downloads the model and voice into `.cache/kokoro/`; allow extra startup time and an internet connection for the download. See [local voice configuration](docs/local-voice.md) for voice options and playback troubleshooting.

For microphone input, leave Mindcraft running and open a second terminal:

```sh
npm run voice
```

Wait for Whisper to load, then open [the microphone panel](http://localhost:8082), click **Enable microphone**, and allow browser microphone access. Hold **F8** while speaking, then release to send; the global shortcut is Windows-only, and the panel button is also available. Andy must be connected to the Minecraft world. Check the displayed transcript if recognition is inaccurate, and use headphones to avoid feedback.

The microphone service listens on loopback only. Whisper downloads its English model to `.cache/whisper/` on first launch and transcribes locally. Disable the microphone in the panel or press **Ctrl+C** in its terminal to stop it. For agent/port configuration and microphone troubleshooting, see [push-to-talk setup](docs/voice-chat.md).

## Use fishing

Give Andy a `fishing_rod`, stand near exposed water, and ask him to fish, or send `!fish()` through the normal in-game command flow. Each call makes one attempt. If no suitable bank or safe casting direction is found, Andy reports that no cast was made. A bite alone is not reported as a confirmed catch without an inventory gain.

The command is registered in `src/agent/commands/actions.js`, the public gameplay skill is `fish(bot)` in `src/agent/library/skills.js`, and casting/waiting helpers live in `src/agent/library/fishing.js`.

# Getting Started
## Requirements

- [Minecraft Java Edition](https://www.minecraft.net/en-us/store/minecraft-java-bedrock-edition-pc) (up to v1.21.11, recommend v1.21.6)
- [Node.js Installed](https://nodejs.org/) (Node v18 or v20 LTS recommended. Node v24+ may cause issues with native dependencies)
- At least one API key from a supported API provider. See [supported APIs](#model-customization). OpenAI is the default.

> [!Important]
> If installing node on windows, ensure you check `Automatically install the necessary tools`
>
> If you encounter `npm install` errors on macOS, see the [FAQ](FAQ.md#common-issues) for troubleshooting native module build issues

## Install and Run

1. Make sure you have the requirements above.

2. Download the [latest release](https://github.com/mindcraft-bots/mindcraft/releases/latest) and unzip it, or clone the repository.

3. Rename `keys.example.json` to `keys.json` and fill in your API keys (you only need one). The desired model is set in `andy.json` or other profiles. For other models refer to the table below.

4. In terminal/command prompt, run `npm install` from the installed directory

5. Start a minecraft world and open it to LAN on localhost port `55916`

6. Run `node main.js` from the installed directory

If you encounter issues, check the [FAQ](https://github.com/mindcraft-bots/mindcraft/blob/main/FAQ.md) or find support on [discord](https://discord.gg/mp73p35dzC). We are currently not very responsive to github issues. To run tasks please refer to [Minecollab Instructions](minecollab.md#installation)

## Online Servers
To connect to online servers your bot will need an official Microsoft/Minecraft account. You can use your own personal one, but will need another account if you want to connect too and play with it. To connect, change these lines in `settings.js`:
```javascript
"host": "111.222.333.444",
"port": 55920,
"auth": "microsoft",

// rest is same...
```
> [!Important]
> The bot's name in the profile.json must exactly match the Minecraft profile name! Otherwise the bot will spam talk to itself.

To use different accounts, Mindcraft will connect with the account that the Minecraft launcher is currently using. You can switch accounts in the launcher, then run `node main.js`, then switch to your main account after the bot has connected.

## Tasks

Tasks automatically start the bot with a prompt and a goal item to acquire or blueprint to construct. To run a simple task that involves collecting 4 oak_logs run 

`node main.js --task_path tasks/basic/single_agent.json --task_id gather_oak_logs`

Here is an example task json format: 

```
{
    "gather_oak_logs": {
      "goal": "Collect at least four logs",
      "initial_inventory": {
        "0": {
          "wooden_axe": 1
        }
      },
      "agent_count": 1,
      "target": "oak_log",
      "number_of_target": 4,
      "type": "techtree",
      "max_depth": 1,
      "depth": 0,
      "timeout": 300,
      "blocked_actions": {
        "0": [],
        "1": []
      },
      "missing_items": [],
      "requires_ctable": false
    }
}
```

The `initial_inventory` is what the bot will have at the start of the episode, `target` refers to the target item and `number_of_target` refers to the number of target items the agent needs to collect to successfully complete the task. 

If you want more optimization and automatic launching of the minecraft world, you will need to follow the instructions in [Minecollab Instructions](minecollab.md#installation)

## Docker Container

If you intend to `allow_insecure_coding`, it is a good idea to run the app in a docker container to reduce risks of running unknown code. This is strongly recommended before connecting to remote servers, although still does not guarantee complete safety.

```bash
docker build -t mindcraft . && docker run --rm --add-host=host.docker.internal:host-gateway -p 8080:8080 -p 3000-3003:3000-3003 -e SETTINGS_JSON='{"auto_open_ui":false,"profiles":["./profiles/gemini.json"],"host":"host.docker.internal"}' --volume ./keys.json:/app/keys.json --name mindcraft mindcraft
```
or simply
```bash
docker-compose up --build
```

When running in docker, if you want the bot to join your local minecraft server, you have to use a special host address `host.docker.internal` to call your localhost from inside your docker container. Put this into your [settings.js](settings.js):

```javascript
"host": "host.docker.internal", // instead of "localhost", to join your local minecraft from inside the docker container
```

To connect to an unsupported minecraft version, you can try to use [viaproxy](services/viaproxy/README.md)

# Bot Profiles

Bot profiles are json files (such as `andy.json`) that define:

1. Bot backend LLMs to use for talking, coding, and embedding.
2. Prompts used to influence the bot's behavior.
3. Examples help the bot perform tasks.

## Model Specifications

LLM models can be specified simply as `"model": "gpt-5.4"`, or more specifically with `"{api}/{model}"`, like `"openrouter/google/gemini-2.5-pro"`. See all supported APIs [here](#model-customization).

The `model` field can be a string or an object. A model object must specify an `api`, and optionally a `model`, `url`, and additional `params`. You can also use different models/providers for chatting, coding, vision, embedding, and voice synthesis. See the example below.

```json
"model": {
  "api": "openai",
  "model": "gpt-5.4",
  "url": "https://api.openai.com/v1/",
  "params": {
    "max_tokens": 1000,
    "temperature": 1
  }
},
"code_model": {
  "api": "openai",
  "model": "gpt-5.4-mini",
  "url": "https://api.openai.com/v1/"
},
"vision_model": {
  "api": "openai",
  "model": "gpt-5.4",
  "url": "https://api.openai.com/v1/"
},
"embedding": {
  "api": "openai",
  "url": "https://api.openai.com/v1/",
  "model": "text-embedding-3-small"
},
"speak_model": "openai/tts-1/echo"
```

`model` is used for chat, `code_model` is used for newAction coding, `vision_model` is used for image interpretation, `embedding` is used to embed text for example selection, and `speak_model` is used for voice synthesis. `model` will be used by default for all other models if not specified. Not all APIs support embeddings, vision, or voice synthesis.

All apis have default models and urls, so those fields are optional. The `params` field is optional and can be used to specify additional parameters for the model. It accepts any key-value pairs supported by the api. Is not supported for embedding models.

## Embedding Models

Embedding models are used to embed and efficiently select relevant examples for conversation and coding.

Supported Embedding APIs: `openai`, `google`, `replicate`, `huggingface`, `novita`

If you try to use an unsupported model, then it will default to a simple word-overlap method. Expect reduced performance. We recommend using supported embedding APIs.

## Voice Synthesis Models

Voice synthesis models are used to narrate bot responses and specified with `speak_model`. This field is parsed differently than other models and only supports strings formatted as `"{api}/{model}/{voice}"`, like `"openai/tts-1/echo"`. We only support `openai` and `google` for voice synthesis.

## Specifying Profiles via Command Line

By default, the program will use the profiles specified in `settings.js`. You can specify one or more agent profiles using the `--profiles` argument: `node main.js --profiles ./profiles/andy.json ./profiles/jill.json`
